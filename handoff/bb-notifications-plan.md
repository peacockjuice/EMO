# EMO: план уведомлений BB

План согласован по смыслу, реализация не начата. Сначала пользователь попросил сохранить текущий проект и handoff в GitHub.

## Цель

EMO показывает состояние выбранных основных веток BB: работает, нужен ответ, ответ готов, ошибка. Не читать текст переписки для догадок о результате. Готовый ответ не означает успешное завершение задачи. Запрос пользователя не всегда останавливает агента.

## Подтверждённые интерфейсы BB

Локальные справочники bb-cli и bb-plugin-authoring описывают thread.active, thread.idle, thread.failed, turn.failed, interaction.pending. События во время отключённого плагина не переигрываются. Нужно зарегистрировать обработчики и затем сверить актуальные состояния. Не опрашивать список веток для обнаружения каждого перехода. Перед реализацией проверить актуальные SDK-типы, снятие pending interaction, ручную остановку и запланированный retry. Поля thread.idle/lastAssistantText не доказывают успех задачи; содержимое сообщения роботу не передавать.

## Порядок реализации

1. Получить реальные события одной выбранной основной ветки. Проверить разрешение запроса, отмену и автоматический повтор. Не включать все проекты и дочерние ветки автоматически.
2. Выбрать четыре различимые реакции из готового набора. Проверить их через существующий HTTP API без прошивки. Не использовать быстрое мигание или инверсию для обычных уведомлений.
3. Создать плагин BB и отдельный режим робота «Уведомления BB». Первичная установка приёмника на плату требует USB. Обновления по Wi-Fi — отдельная задача.
4. Передавать минимальное состояние, идентификатор/номер обновления и срок действия. Защитить приёмник отдельным ключом; ключ вне Git. Передавать из процесса, имеющего доступ к домашней сети (при удалённом сервере BB нужен исполнитель на Mac).
5. Приоритет: нужен ответ → ошибка без ожидающего повтора → ответ готов → работает → живой характер. Объединять близкие завершения, удалять устаревшие поздравления. Если другой агент ещё работает, после короткой радости вернуть рабочее состояние.
6. Ручной выбор эмоции, сцены или demo выключает режим BB. Входящие события не могут включить его обратно. Для возобновления нужна кнопка «Уведомления BB». После перезагрузки — auto.
7. Продлевать срок действия состояния только пока включён режим BB. При потере связи вернуть живой характер. После восстановления сверить состояние; не проигрывать старую очередь. Ошибки доставки не должны блокировать агентов. Хранить дедупликацию и учитывать перезапуск плагина.
8. Проверить запрос/ответ, остановку, ошибку с повтором, несколько веток, дубли, старые команды, отключение Mac, перезапуск BB и ручное управление. Обновить handoff по фактическим результатам.

## Не входит в первую версию

Звук, новые датчики, оценка качества работы агентом, чтение кода/переписки, автоматическое управление агентами, интернет-доступ к роботу и ссылки на ветки в OLED. Текущий 30-минутный тест характера отдельно отложен пользователем; не запускать его под видом проверки уведомлений.
